# Funda scraper repair

Goal: restore installation, the documented API and extraction, and offer the
local browser principles requested from the ScrapingBee article.

Architecture: keep SearchRequest and Property; separate transport, HTML parsing
and orchestration. Sessions live in memory. Store exported property data only.
Direct HTTP remains the default; the local browser is an explicit choice. No paid provider or credentials are required.

1. Reproduce legacy API failures with deterministic tests. Replace live-network
   assertions with representative synthetic search/detail fixtures and a local
   HTTP server exercising the real requests transport.
2. Unify package metadata for Python 3.9+, fix incompatible syntax, restore both
   constructor forms and CLI. Remove outdated pins and align requirements.
3. Parse JSON-LD arrays/graphs and modern links, use labelled dt/dd features,
   retain fallback selectors, support empty results and both URL formats.
4. Add session-based HTTP, Camoufox transports. Bound timeouts,
   retries and pacing; stop on CAPTCHA. Keep credentials out of errors and URLs.
   Never save browser state or raw pages. Test error paths and end-to-end export.
5. Run full pytest, lint, builds, clean installation, CLI and small live probes.
   Review the diff independently, fix findings, push to the fork and open a PR.

Limits: CAPTCHA-free access depends on Funda and network/provider conditions.
A future Cloudflare API/queue can call a browser worker; it is not part of this repair.
Synthetic fixtures prove parser behavior, not compatibility with every live page.
